# portfolio

Personal site — React 19, Vite, TypeScript, Tailwind v4.

## Running it

```bash
npm install
npm run dev      # dev server
npm run build    # typecheck + production build
npm run lint
```

## Writing

Edit Markdown files in `content/writing/`. The initial `Working With VLAs/`
folder is a copy of the Obsidian notes; editing it does not change the vault.
Subfolders are supported. Every article starts with YAML metadata:

```yaml
---
title: "My article"
slug: "my-article"
date: "2026-11-22"
description: "A short description for the writing list and link previews."
tags: [robot-learning]
---
# My article

Write the article here.
```

`title`, `date`, and `description` are required. `slug` is optional (defaults to
its filename), but keep it stable once published so existing links keep working.
`tags` are optional and used for search. Add `draft: true` to exclude a post.
Reading time is calculated automatically. Posts appear newest first.

`npm run dev` and `npm run build` sync the folder automatically. While the dev
server is running, editing, adding, or deleting Markdown refreshes the preview.
You can also run `npm run refresh-blog` to sync manually—this now reads local
files and makes no Notion requests.

Obsidian links such as `[[Working With VLAs - Data|Data]]` become internal article
links. Vault paths in those links are resolved by note filename. Standard
Markdown links also work; use `/writing/<slug>` for internal links. Put images in
`public/writing-assets/` and reference `/writing-assets/<filename>` in Markdown.

`public/posts/` and `src/data/blog-posts.json` are generated files; edit the
source folder instead. Deleted or draft articles are removed from generated
output. Invalid metadata or unresolved wikilinks stop the sync without replacing
the last successful output. Commit your Markdown changes and deploy to publish;
the sitemap and share cards are rebuilt from the same local content.

## Projects

Add the entry to `src/data/projects.ts` and drop the clip in `public/videos/`,
then:

```bash
npm run posters
```

That writes `public/posters/<name>.webp` from each clip's first frame. The cards
reference it by deriving the path from the video, so there is no poster field to
set and the still can never disagree with the video it stands in for.

Videos use `preload="none"` and WebP posters. They load on hover, keyboard focus,
or a touch tap on the Projects page, and stop when leaving the viewport.
Posters keep the initial page load lightweight.

## SEO

`npm run build` syncs local writing, then runs `make-sitemap.js`, which writes `public/sitemap.xml`
and `public/robots.txt`. Routes come from `src/lib/nav.ts` and posts from
`blog-posts.json`, so neither needs a second list kept in sync. Output carries no
build timestamp, so an unchanged site rebuilds to an identical file.

Change the domain at the top of `make-sitemap.js` if it moves.

Article share previews are generated by `scripts/build-article-previews.js`
after Vite builds. Each published post gets static HTML metadata and a 1200×630
PNG in `dist/social`, using the checked-in blog metadata and bundled licensed
font. Vercel's `cleanUrls` setting serves those article HTML files at their
existing extensionless URLs. The development server does not generate these
cards; run `npm run build` to inspect them in `dist/social`.
If the domain changes, also update that script and the metadata in `src/App.tsx`.

## Layout

```
src/
  components/                 navigation, search, video previews, cursor trail
  lib/                        route definitions and shared formatting helpers
  pages/                      home, experience, projects, writing, articles
  data/                       jobs, projects, generated blog metadata
```

Navigation is keyboard-first: `1`–`4` jump to sections, `j`/`k` step through
them, `/` or `⌘K` opens the palette.

## Design and maintenance

The site is light-only, with a 640px content column, shared color tokens in
`src/index.css`, and a single navigation definition in `src/lib/nav.ts`.
Page headings are available to screen readers without adding visible titles.
Keep project video behavior in `ProjectVideo.tsx` and use `SiteLink.tsx` for links
that may point to either local articles or external sites.

Markdown rendering and the command palette load only when needed. Article
transitions use CSS and respect reduced-motion preferences; automatic video
playback also respects that setting. The Home music shelf loads audio only after a cover is clicked. Cover palettes
and track paths live in `src/data/music.ts`; assets live in `public/music`.
Clicking the active cover pauses playback. Playback and the turtle/ASCII palette persist across routes. The active track loops
until paused by clicking its cover on Home.

Run `npm run lint`, `npm run format:check`, and `npm run build` before committing.
`npm run format` applies the repository's formatting. Poster generation requires
FFmpeg. Writing sync, normal development, and builds use checked-in local content;
no Notion account or credentials are needed.
